# Monetization receipts (src/server/Monetization.luau)

- DataStore "PurchaseHistory", key `{PlayerId}_{PurchaseId}`. Values: `{status="pending", at}`, `{status="done", at}`, or legacy `true` (meaning done, from before sprint 4).
- Flow (sprint 4): UpdateAsync only reserves (writes pending). Then the grant runs outside UpdateAsync (handlers may yield). Then a second UpdateAsync marks it done. If the grant fails or returns false, RemoveAsync drops the marker and the decision is NotProcessedYet. If marking done fails, it still returns PurchaseGranted.
- Why: a grant inside the UpdateAsync callback could run twice when the callback is re-run.
- Sprint 5: every attempt writes its pending marker with its own `token` (a GUID). It grants only if the value UpdateAsync returned has that token. Mark-done writes only over our own token; if another attempt took the receipt over, it leaves that marker and returns NotProcessedYet. Known limit: if a handler yields past 120 s and another server takes over meanwhile, both still grant. Tokens can't stop that, because the grant and the done-write can't be made atomic.
- Sprint 6: product handlers must not yield. The grant runs right after the reserve's token check, through `grantWithoutYield` (coroutine.resume). If it yields, it's closed and counts as a failed grant (the marker is removed, NotProcessedYet). PENDING_TIMEOUT is now 600 s, exposed as `Monetization._PENDING_TIMEOUT`. This closes the sprint-5 "known limit" in practice: a stale takeover would now need a DataStore call to stall for 600 s.
- Sprint 7 (replaces the sprint-6 cancel): `runGrant` runs the handler in a coroutine and checks coroutine.status. If it yielded, it is NOT closed (cancelling could double-grant or leave half-done effects). processReceipt warns, returns NotProcessedYet and keeps the pending marker (no RemoveAsync). When the handler finishes later and returned true, `markDone` records done (own token only). If it fails late, the marker is left to go stale. PENDING_TIMEOUT is now 180 s. Handlers still must not yield; this is only a safety net.
- Sprint 8 (replaces the takeover): PENDING_TIMEOUT is gone. ANY pending marker = busy, forever; only the attempt that owns its token replaces it. Values now also include `{status="released", at, token}` (refused or failed grant), which can be reserved again. RemoveAsync is no longer used. The handler runs via task.spawn (`runGrant`); still running → NotProcessedYet. Late results are written by `keepWriting` (UpdateAsync over own token, task.wait backoff 0.5 s doubling to 30 s, until the call succeeds). A failed reserve also spawns a release, in case the write landed. A failed sync mark-done returns PurchaseGranted and retries in the background.
- Known cost of no takeover: a server that dies between reserve and the final write (more likely if a handler yields) leaves the purchase stuck pending forever (never given, never retried successfully). Fixing one needs a manual DataStore edit.
- Testing in Studio: the Studio place isn't Rojo-synced. To run the spec without editing the place, start a playtest and paste the module's receipt code and the spec into execute_luau (Server).
- `Monetization._processReceipt(receipt, store, grant, buyer)` and `_RETRY_FIRST` are test hooks; `Monetization.cloud.spec.luau` uses a fake store.
